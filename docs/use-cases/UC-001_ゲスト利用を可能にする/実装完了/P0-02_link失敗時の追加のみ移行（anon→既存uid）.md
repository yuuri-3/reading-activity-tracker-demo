# P0-02 link 失敗時の追加のみ移行（anon→ 既存 uid）

このチケットは `linkWithPopup` が失敗するレアケース（例: Google 資格情報が既に別 uid に紐付いている）でも、ゲストデータを失わないためのフォールバックです。

## ゴール

- link できない Google アカウントでも、ゲスト（匿名）で作ったデータがログイン後に見える
- 既存クラウドデータを消さない（削除/全置換/上書きしない）

## 対象

- [src/app/auth/AuthContext.tsx](../../../src/app/auth/AuthContext.tsx)
- Firestore: `users/{uid}/tags|books|records`
- Toast: sonner（`toast`）

## 受け入れ条件

- [x] アカウントを持たない Google アカウントに連携できる
- [x] 既存アカウントを持つ Google アカウントを選択した場合、追加コピーの旨をダイアログで表示し、ユーザーに確認する
- [x] 二回目の Google アカウント選択で一回目と異なるアカウントを選んだ場合、再度ユーザーに確認する
- [x] 二回目に選択した Google アカウントに連携し、データも既存のものと移行したものすべて表示される

## 作業内容

### 追記事項（合意済み方針）

#### トリガ条件

- `signInWithGoogle()` にて、匿名ユーザーで `linkWithPopup` が `auth/credential-already-in-use` 等で失敗した場合

#### 現状の挙動（この対応がない場合）

- `linkWithPopup` が `auth/credential-already-in-use` 等で失敗すると、Google ログインには進まず「ゲストのまま利用できます」というエラー表示で終了する
  - ゲストで作ったデータは引き続き見える（匿名状態が維持される）
  - ただし「その Google アカウントでログインした状態」にはなれないため、既存 uid 側のデータは見えない
- その場で再度ログインを試し、別の Google アカウントを選べば連携できる可能性はある
  - しかし「すでに別 uid に紐付いている Google アカウントでログインしたい」ケースは救えない

### 移行アルゴリズム（実装要件）

#### 0. 最終確認（link 失敗時のみ追加）

- `linkWithPopup` が `credential-already-in-use` 等で失敗した場合は、フォールバックで uid が変わる前提になるため、ユーザーに最終確認を出す
  - 続行: Google ログイン（popup）→ 追加のみコピーを実施
  - キャンセル: Google ログインを開始しない（匿名状態を維持）

1. （まだ anon のまま）`users/{anonUid}/tags|books|records` を `getDocs()` で読み出し、メモリに保持する
2. その後 `signInWithPopup` で Google アカウントにログインする（P0 は popup 前提）
   - redirect はページリロードで 1 のメモリが失われるため、P0 の「追加のみ移行」対象外
3. ログイン後 uid に対して、`tags → books → records` の順で `writeBatch()` + `setDoc(..., { merge: true })` 相当で「追加のみ」書き込み

4. （可能なら）クリーンアップ

- 移行が成功した場合に限り、anon 側のアカウント/データ削除をベストエフォートで試みる
- 失敗しても、移行自体は成功扱いのままにする（安全優先）

#### 冪等性

- docId を維持し、`merge: true` 相当で書くことで、同じデータを再コピーしても破綻しないこと

#### クリーンアップ

- 移行前に削除はしない（クライアントだけで削除まで行うと失敗時に危険）
- 移行成功後に限り、anon 側のデータ/アカウント削除をベストエフォートで試す

### UI/UX

- P0-01 と同様に、Google ログイン開始前に統合確認ダイアログを出す
  - キャンセル時は Google ログインを開始しない（匿名状態を維持）
- link 失敗でフォールバックに入る場合は、追加のみコピーを実施する直前に最終確認を出す
  - キャンセル時はフォールバックを開始しない（匿名状態を維持）
- 最終確認で「続行」を押した後、Google アカウント選択が再表示される場合がある（仕様）
- 移行中/失敗時は既存 UI の範囲で通知する
  - 失敗時は Toast で最小限のエラー表示

## 非ゴール

- 重複排除の高度化、競合解決（updatedAt 上書き）は行わない
- redirect フローでの「追加のみ移行」の対応（必要なら P1 で永続退避方式を検討）
