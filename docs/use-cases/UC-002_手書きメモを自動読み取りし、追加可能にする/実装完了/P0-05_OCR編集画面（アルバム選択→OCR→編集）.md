# P0-05 OCR 編集画面（アルバム選択 →OCR→ 編集）

このチケットは、OCR の最小フロー（画像選択 →OCR 実行 → テキスト編集）を“機能フラグ配下でのみ”提供する単位です。まだ保存先への保存は行いません（次チケット）。

## ゴール

- フラグ ON のときだけアクセスできる OCR 編集画面を用意できる
- アルバム選択した画像を元に OCR を実行し、結果テキストを編集できる
- 元画像のサムネイルプレビューを表示できる（ズーム不要）
- 再試行（画像選び直し）で結果を置き換えられる（履歴は持たない）

## 決定事項

- 機能フラグはビルド時 env で制御する
  - env 名: `VITE_FEATURE_OCR`
  - `VITE_FEATURE_OCR=1` のときのみ OCR 編集画面の導線/ルートを有効化する
- ルートは一旦 `/ocr/edit` とする（導線は後で変更してよい）
- 導線は一旦「ホーム画面に OCR ボタンを仮設置」する（導線は後で変更してよい）
- UX（MVP）
  - OCR 実行中はローディング表示し、多重実行を防ぐ（主要ボタンを無効化）
  - P0 では「キャンセル（実行中断）」は提供しない
  - 失敗時のリトライ導線は「画像を選び直す」のみ（同じ画像での再実行は P0 では提供しない）
  - 画像を選び直した場合、編集テキストは保持し、次の OCR 成功時に置き換える
    - 画像が変わったことが分かる補助文言を表示する（例: 「新しい画像を選択しました。OCR を実行するとテキストが置き換わります。」）
- 画像の取り扱い（MVP）
  - 入力: `accept="image/*"` のまま選択できる
  - 形式: JPEG/PNG のみ（読み込み時に MIME で判定して弾く）
  - サイズ: 10MB 上限（超過時はエラー表示）
  - 回転（EXIF 含む）: P0 では対応しない（表示が横になる可能性は既知。P1-02 で対応）

## 画面状態（MVP）

- 未選択: 画像未選択。OCR 実行ボタンは無効
- 選択済み: サムネ表示。OCR 実行ボタン有効
- 実行中: ローディング表示、ボタン類は基本無効（多重実行防止）
- 成功: 編集テキスト欄に結果を反映
- 失敗: エラーメッセージ表示、再試行導線を提示（画像選び直し）

## 文言（MVP）

- OCR 失敗: 「読み取りに失敗しました。画像を選び直してください。」
- 画像形式エラー: 「対応していない画像形式です。JPEG または PNG を選んでください。」
- 画像サイズエラー: 「画像サイズが大きすぎます（10MB まで）。別の画像を選んでください。」
- 同意（未同意時）
  - ダイアログ文言は P0-04 の既存に従う
  - 「キャンセル」時は OCR を実行しない（状態は変更しない）
- 画像未選択（補助テキスト）: 「画像を選択してください」

## 受け入れ条件

達成チェック:

- [x] フラグ OFF では OCR 編集画面への導線/ルートが存在しない（ユーザーから見えない）
- [x] フラグ ON で、アルバム選択 →OCR 実行 → 編集ができる
- [x] OCR 結果は自動保存されず、必ず編集画面上に留まる
- [x] 元画像のサムネイルが表示される
- [x] 再試行（画像選び直し）で OCR 結果が置き換わる

## 作業内容

### 1) 画像選択（MVP: アルバム）

- Web の `<input type="file" accept="image/*">` 相当で選択できる

### 2) OCR 実行

- P0-04（同意）→ P0-03（OCR API）→ P0-02（callable）を利用して実行

#### 2-a) （追加）同意ガードの接続

- P0-04 で実装した「初回のみ同意ダイアログ」を、P0-05 の実導線（OCR 実行ボタン/開始アクション）に接続する
  - 未同意: ダイアログ表示 → 「続行」で `consentAccepted=true` を保存 → OCR 実行
  - 「キャンセル」: OCR 実行しない
  - プライバシーポリシーリンク: `/sanctum/privacy` を新しいタブ/ブラウザで開く
- 参照実装:
  - `ocrHandwrittenMemoLocalState`（`consentAccepted`）
  - `ocrHandwrittenMemoConsent`（同意判定/保存/URL 生成）

### 3) 編集 UI

- テキスト入力で編集できる
- サムネイル表示
- 再試行（画像選び直し）ボタン
