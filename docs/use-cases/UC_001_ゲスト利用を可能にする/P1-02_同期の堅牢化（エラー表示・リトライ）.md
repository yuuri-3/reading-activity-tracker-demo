# P1-02 同期の堅牢化（エラー表示・リトライ）

## ゴール

- link/移行が途中で落ちても再実行が安全で、ユーザーが状況を理解できる

## 対象

- 認証/移行フロー: [src/app/auth/AuthContext.tsx](../../../src/app/auth/AuthContext.tsx)
- UI（エラー表示）: [src/app/auth/components/SignInScreen.tsx](../../../src/app/auth/components/SignInScreen.tsx)
- 通知（Toast）: 既存の Toast 実装（sonner 等）を利用

## 実装状況

Status: ⬜ 未着手

## 受け入れ条件

達成チェック:

- [ ] 同じ操作を連打しても、ログイン/移行処理が同時に複数走らない
- [ ] 失敗時に最低限のエラーメッセージが表示され、リトライできる

## 作業内容

- link/移行が失敗した場合に Toast で最小限の通知を行う
- 連打や二重起動で多重実行されないようガードする
  - 例: `signInWithGoogle()` 実行中フラグ
  - 例: 追加のみ移行の実行中フラグ

## 非ゴール

- 文言の作り込み・デザイン刷新（既存の SignInScreen / Toast の範囲に留める）
- 高度な競合解決（updatedAt ベースのマージ等）の導入

## 注意

- UX の詳細（文言や表示位置）は、既存の SignInScreen のエラー表示 / sonner の Toast の範囲に留める
