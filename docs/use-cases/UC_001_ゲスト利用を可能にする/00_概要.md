# UC_001 ゲスト利用を可能にする

このユースケースは、未ログインでも全機能を使えるようにし、ログイン時にゲストデータを Firestore 上で安全に引き継げるようにするための実装指示です。

## 決定事項

- ゲストは匿名認証ユーザー（`user.isAnonymous === true`）として扱う（ユーザーが明示的に選んだ時のみ `signInAnonymously()`）
- books/records/tags は常に Firestore を SSoT にする（LocalBackend は作らない）
- Google ログインは link 優先（基本は `linkWithPopup`）
- popup が利用できない場合のみ redirect をフォールバック
- link 失敗時のみ anon→ 既存 uid へ「追加のみコピー」（上書きしない / anon 側は削除しない）
- 統合先はユーザーが選択した Google アカウント（= 現在のゲストデータに紐づける認証情報）。Google のアカウント選択を開く前に統合確認ダイアログを出す
- 計測（P1）は「匿名ユーザーの初回 record 作成」1 回のみ（Firebase Analytics/GA4）
- Cookie 同意ボタンは作らないが、プライバシーポリシー導線はアプリ内に用意する
- link 失敗（追加コピー）/ 匿名認証失敗などの通知は既存 UI（SignInScreen のエラー表示 / Toast）で行う

## 全体アーキテクチャ方針（最小変更）

- 画面やコンポーネントは既存通り AppContext 経由で CRUD を呼ぶ（差し替えない）
- AuthGate は「ログイン必須」ではなく「未ログイン時に SignInScreen を表示」する
  - SignInScreen の「ログインせず利用する」選択時のみ匿名認証で通す
- AppContext は Firestore 購読/CRUD を継続する

## 自分用補足メモ

### 「ゲスト = 匿名認証ユーザー」の意味

- この UC での「ゲスト」は「未ログイン」ではなく、Firebase Auth の匿名認証（Anonymous Auth）でサインイン済みのユーザーを指す。
- `signInAnonymously()` が成功すると `currentUser` が入り、`user.isAnonymous === true` になる（= 匿名ユーザーとしてログイン中）。
- 「ユーザーが明示的に選んだ時のみ `signInAnonymously()`」は、アプリ起動時などに自動で匿名ユーザーを作らず、SignInScreen の「ログインせず利用する」を押した時だけ匿名認証する、という方針。

### 「Google ログインは link 優先」の考え方

- `linkWithPopup` は「いまのユーザー（匿名ユーザー）に Google の認証情報を紐づける」操作。
- link が成功すると uid は変わらない（匿名 →Google に“昇格”するイメージ）ため、Firestore の保存先が変わらずデータ移行が不要になる。
- 逆に `signInWithPopup`（単純ログイン）だと uid が切り替わりやすく、匿名中に作ったデータを移す必要が出て複雑化しやすい。

### 「link 失敗時は追加のみコピーに落とす」の意味

- link が失敗する代表例：その Google 資格情報が既に別ユーザーに紐づいている（例：`auth/credential-already-in-use`）。この場合、同じ uid のまま統合できない。
- そのときは Google 側の既存アカウントでログインして uid を切り替えた上で、匿名ユーザー（`anonUid`）側のデータをログイン後ユーザー（`googleUid`）側へ「追加だけ」コピーして救済する。
- 「追加のみ」= (1) 上書きしない（既存データは壊さない/潰さない） (2) コピー元（anon 側）を削除しない。
