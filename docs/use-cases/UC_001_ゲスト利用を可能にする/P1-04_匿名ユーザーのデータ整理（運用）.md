# P1-04 匿名ユーザーのデータ整理（運用）

## ゴール

- link 不可ケースで anon→uid へ移行したあと、古い anon 側のデータ/ユーザーが残る問題を運用として整理する

## 対象

- 運用方針（本ドキュメント）
- （必要になった場合）サーバー側の整理手段（Cloud Functions / バックオフィス等）

## 実装状況

Status: ⬜ 未着手

## 受け入れ条件

達成チェック:

- [ ] link 不可ケースで発生する「孤立 anon データ」の扱い方針が決まっている（削除/放置/定期掃除など）
- [ ] 方針が運用として文書化され、関係者が参照できる
- [ ] P0/P1 のクライアント実装では anon 側データを削除しない方針が維持されている

## 作業内容

- サーバー側（Cloud Functions / バックオフィス）で anon の孤立データを掃除する方針を検討
- もしくは、anon 側が残ってもコストが許容なら何もしない

## 非ゴール

- クライアントのみで anon 側データを削除すること

## 注意

- クライアントだけで anon 側データを削除すると失敗時に危険なので、P0/P1 では「削除しない」方針を維持する
