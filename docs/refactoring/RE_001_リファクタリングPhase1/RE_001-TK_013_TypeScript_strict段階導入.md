# P1-RE_001-TK_013 TypeScript の `strict` を段階導入する

このチケットは、TypeScript の厳密さを段階的に上げ、将来の事故（undefined/null/型抜け）を早期検知できるようにします。

## ゴール

- `tsconfig.json` の厳密設定が方針化され、段階的に強化される
- 追加された厳密化による修正が、局所的・理解可能な形で入る

## 対象

- `tsconfig.json`
- 型エラーが出やすい箇所（導入時に判明する範囲）

## 実装状況

Status: ⬜ 未着手

## 受け入れ条件

- [ ] まずは「strict 化の方針」と「導入順」が決まっている
- [ ] 導入した設定で `npm run typecheck` が通る
- [ ] 新規コードで型抜けが増えない（最低限のガードがある）

## 作業内容

### 1) 方式決め（段階案）

- 案 A: いきなり `strict: true`（ただし修正量が大きい可能性）
- 案 B: 小刻みに強化（例: `noImplicitAny` / `strictNullChecks` など順番に）
- 案 C: 新規ファイルだけ厳密（運用ルールで縛る）

### 2) 最小差分で適用

- 影響が少ない設定から入れる
- 型ガード/`as const`/補助関数で修正を局所化

## 非ゴール

- すべてのコードを完璧にジェネリクス化する

## 注意

- `skipLibCheck` は維持でも良い（速度優先）。ただし不整合が見えにくくなる点は記録する
