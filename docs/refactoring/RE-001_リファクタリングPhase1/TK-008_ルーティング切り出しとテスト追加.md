# P1-TK-008 ルーティングを切り出し、ユニットテストを追加する

このチケットは、`App.tsx` に密集しているルーティング処理を小さなモジュールに切り出し、変更耐性を上げます。

## ゴール

- ルート解析/生成が `App.tsx` から分離され、見通しが良くなる
- ルート解析の境界条件（basePath/末尾スラッシュ等）をテストで固定できる

## 対象

- 現状のルーティング実装: [src/app/App.tsx](../../../src/app/App.tsx)
- 既存ユーティリティ: [src/app/utils/navigation.ts](../../../src/app/utils/navigation.ts)
- 新規（案）: `src/app/utils/router.ts`（parse/generate を集約）
- テスト: Vitest（`src/app/utils/router.test.ts` など）

## 実装状況

Status: ⬜ 未着手

## 受け入れ条件

- [ ] `App.tsx` からルート判定ロジックが切り出されている
- [ ] `parseRouteFromPath()` / `toPathname()` 相当の関数にユニットテストが付く
- [ ] 既存のページ遷移（戻る/進む含む）が壊れない

## 作業内容

### 1) API 設計

- ルート表現（型）を決める（既存の分岐をそのまま型にする）
- `parseRouteFromLocation(location)` と `toPath(route)` のように「入出力」を固定

### 2) 切り出し

- `App.tsx` から純粋ロジックを移動し、UI 側は状態反映だけに寄せる

### 3) テスト

- base path / 空パス / 不正パス / 末尾スラッシュ等のケースをテスト

## 非ゴール

- React Router 等の追加依存導入

## 注意

- 既存の base path 対応は維持する（`navigation.ts` と整合）
