# P1-TK-022 外部連携まで含めた保証（E2E/エミュレータ/ステージング）の方針決定と導入

このチケットは、Storybook の UI 品質ゲートとは別に、外部連携（Firebase/Functions 等）まで含めた保証をどこまで・どうやって行うかを決め、最小構成で導入します。

## ゴール

- 「何を E2E で保証するか」「どの環境で回すか（エミュレータ/ステージング/本番）」の方針が決まっている
- 最小限の E2E シナリオが CI で実行できる（頻度・所要時間・失敗時の扱いも決まっている）

## 対象（例）

- E2E テスト基盤（Playwright など）
- Firebase Emulator / ステージング環境の運用
- CI ワークフロー（nightly / main マージ後 / 手動実行など）

## 関連

- 元チケット: [TK-003 CI に typecheck + test-storybook を追加](./実装完了/TK-003_CIにtypecheckとtest-storybook追加.md)

Status: ⬜ 未着手

## 受け入れ条件

- [ ] E2E の対象範囲（重要導線）と非対象範囲が明文化されている
- [ ] 実行環境（エミュレータ/ステージング/本番）と、そのメリデメが整理されている
- [ ] CI への組み込み方針（いつ回すか、失敗時にマージ/デプロイを止めるか）が決まっている
- [ ] 最小シナリオが 1〜数本動く（例: 起動 → 基本操作 → 保存/取得の確認）

## 作業内容（概要）

- 保証レイヤーの整理（Unit/Vitest、Storybook、E2E の役割分担）
- 選択肢比較（エミュレータ中心 / ステージング中心 / ハイブリッド）
- 最小シナリオとデータ準備（seed）方針を決める
- CI 組み込み（実行頻度、タイムアウト、ログ/動画/スクショ保存方針）

## 非ゴール

- すべての導線を E2E で網羅する（段階導入を前提）
