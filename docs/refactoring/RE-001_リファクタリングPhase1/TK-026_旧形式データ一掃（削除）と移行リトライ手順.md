# P1-TK-026 旧形式（日付文字列・BookMemo 配列）データ一掃（削除）と移行リトライ手順

このチケットは、TK-011 で Timestamp 化 / BookMemo サブコレクション化へ移行した後、
旧形式（例: `createdAt/startTime/endTime` の日付文字列、Book の `memos: BookMemo[]` 配列）を将来的に一掃（削除）して保守負債を減らすための運用・手順を整備します。

また、移行後に問題が見つかった場合に「バックフィルを修正して旧データから移行をリトライする」ための手順も、このチケットで定義します。

## ゴール

- 旧形式データの削除方針（削除対象、削除単位、削除前提）が決まっている
- 移行後に問題が見つかった場合の「バックフィル修正 → 旧データからリトライ」の手順が文書化されている
- 削除/リトライに必要なバックアップと復元手順が文書化されている

## 対象

- データモデル: Timestamp / BookMemo サブコレクション（TK-011 の成果物）
- バックフィル処理（再実行・再移行を含む）
- バックアップ/復元手順（運用）

## 実装状況

Status: ⬜ 未着手

## 受け入れ条件

- [ ] 旧形式データ削除の対象が明確（例: 旧フィールド、旧配列など）
- [ ] 削除前のバックアップ方法が決まっている
- [ ] 問題発生時に「バックフィル修正 → 旧データから再移行」を実行できる手順がある
- [ ] 削除後に問題が発覚した場合の復旧（バックアップ復元 → 再移行）が手順化されている
- [ ] 実施タイミングに関する条件は、本チケット着手時に検討して決める

## 作業内容（案）

### 1) 削除方針の決定

- 削除対象（旧フィールド/旧配列/旧コレクション）を列挙
- 削除対象が残っていても「新形式のみ表示」が崩れないことを前提にするかを決める

### 2) リトライ手順（バックフィル再実行）

- 失敗の分類（データ欠落/型不整合/権限/タイムアウトなど）
- バックフィルの修正ポイントと再実行手順
- 冪等性の担保（同じユーザー/同じドキュメントに何度流しても壊れない）

### 3) バックアップ/復元

- バックアップ取得（削除前に必須）
- 復元 → 再移行の手順（削除後に問題発覚した場合）

## 非ゴール

- TK-011 の移行実装そのもの（別チケット）

## 注意

- 既存データが重要なため、「削除できる」より「復元できる」を優先する
