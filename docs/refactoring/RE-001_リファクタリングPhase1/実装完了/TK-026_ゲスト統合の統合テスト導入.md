# P1-TK-026 ゲスト統合の統合テスト導入

> 本チケットは TK-010 に統合済み。以後の更新は TK-010 を参照。

ゲスト統合フローの実運用に近い保証を得るため、SDK/外部依存を含む統合テストを導入する。

## ゴール

- ゲスト統合の主要フローを統合テストで検証できる
- 環境依存の不具合（SDK 挙動差・権限・ネットワーク）を早期に検知できる

## 対象

- ゲスト統合フロー（backend merge / client-side copy）
- Firebase Auth / Firestore / Functions

## 実装状況

Status: ✅ 完了（TK-010 に統合）

## 受け入れ条件

- [x] 自動/手動の統合テストシナリオが定義されている
- [x] backend merge の自動テストがエミュレータで実行できる
- [x] 手動検証（client-side copy）を含む実行手順がドキュメント化されている

## 作業内容

### 1) シナリオ定義

#### 自動テスト（エミュレータ）

- backend merge: 成功
- backend merge: 期限切れ（`deadline-exceeded`）
- backend merge: 権限不足（異なるユーザーでの preview）
- backend merge: 不正シークレット（`permission-denied`）

#### 手動シナリオ（実運用に近い検証）

- client-side copy: 成功/失敗/重複データ
- アカウント不一致の確認フロー

### 2) 実行環境の決定

- 自動テスト: Firebase Emulator Suite（auth/firestore/functions）
- 手動検証: ステージング
  - 実運用に近い SDK 挙動・権限・ネットワーク差分の確認用

### 3) テスト実装

- 自動テスト: [src/app/firebase/guestMerge.integration.test.ts](../../../src/app/firebase/guestMerge.integration.test.ts)
- テストデータ作成/後始末の自動化（Rules 迂回での seed + cleanup）
- 実行結果の判定（成功/失敗の基準）を明文化

### 4) 実行手順

#### 自動テスト（エミュレータ）

- `npm run test:guest-merge`
  - functions の build を含む
  - macOS で Java 環境が必要な場合は `npm run test:guest-merge:mac`

#### 手動検証（ステージング）

1. `VITE_ENABLE_BACKEND_GUEST_MERGE=false` にして client-side copy を強制
2. 匿名ユーザーでデータ作成（tags/books/records）
3. Google ログインで統合
4. 期待結果:
   - 既存データが重複せずに統合される
   - 失敗時は UI で復旧導線が表示される
5. `VITE_ENABLE_BACKEND_GUEST_MERGE=true` に戻し、backend merge 側を通常運用
