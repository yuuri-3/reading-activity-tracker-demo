# P2-TK-020 `npm audit` 指摘（moderate など）への対応計画を作る

このチケットは、依存導入時に検知される脆弱性（moderate 等）について、運用上の対応方針と更新計画を作ります。

## ゴール

- 依存の脆弱性対応が「気づいた人が都度対応」にならない
- 更新のタイミング/許容範囲/例外が決まっている

## 対象

- `package.json` / `package-lock.json`
- CI（導入する場合）

## 実装状況

Status: ⬜ 未着手

## 受け入れ条件

- [ ] `npm audit` の結果を記録し、対応方針（今すぐ/定期/無視条件）が決まっている
- [ ] 可能なら安全にアップデートできるものは更新されている
- [ ] 更新後も `npm run build` / `npm run test-storybook` が通る

## 作業内容

- `npm audit` の結果を整理（影響・到達可能性・修正有無）
- 影響が小さいものから段階的に更新
- CI に audit を入れる場合は、fail 条件（severity）を決める

## 非ゴール

- すべての指摘をゼロにする（破壊的更新が必要なら別途判断）
